# curata: agent instructions

## What is curata

Curata is the company brain: sensors feed it, policy shapes it, gates validate it, and everything learned flows back to every agent and every human on the team. This repo is the open-source implementation - agents write structured pages via MCP, humans review and annotate them, and agent outputs become the next agent's inputs so the knowledge loop compounds instead of resetting every session.

When describing curata in commits, docs, or to a user, use this framing rather than "just a wiki" or "notes app."

## Repo layout

- `src/app` - Next.js App Router. Page UI, `/api/*` routes (mcp, pages, auth, well-known discovery endpoints), and the public `/p/<org>/<slug>` routes
- `src/components`, `src/hooks`, `src/lib` - shared UI and server logic
- `src/generated` - Prisma client plus the kazam renderer/SDK output, regenerated by `pnpm generate`. Do not hand-edit
- `src/middleware.ts` - AUTH_MODE-branched request routing, rate limiting, content negotiation
- `packages/cli` - the `curata` CLI package
- `packages/mcp-server` - standalone MCP server package. The app also has a built-in MCP server under `src/app/api/mcp`
- `prisma/schema.prisma` and `prisma/migrations` - database schema and migration history
- `seed/` - seed content: getting-started pages, templates, workflows
- `skills/` - Claude Code plugin skills (curata-plan, curata-read, curata-write, curata-setup, curata-workflow, curata-capture, curata-review, send-it)
- `scripts/` - maintenance scripts (git hooks install, home seeding, concept normalization)
- `docs/` - generated reference docs (agents-reference.md, agl-reference.md) plus semantic-tagging.md
- `tests/` - Vitest suite, one file per feature area

## Dev commands

- `pnpm dev` - Next.js dev server (webpack). Or run `./dev.sh` for full first-run setup: starts Postgres via Docker, bootstraps `.env`, installs deps, runs `pnpm generate`, pushes the schema, then starts the dev server
- `pnpm build` - runs `pnpm generate` then `next build`
- `pnpm generate` - regenerates the Prisma client, the kazam SDK/renderer output, and the auto-generated docs. Rerun after touching `prisma/schema.prisma` or kazam templates
- `pnpm test` / `pnpm test:watch` - Vitest, tests live in `tests/*.test.ts`
- `pnpm lint` - ESLint via `eslint-config-next`. Fix lint errors before opening a PR
- `docker compose up` - Postgres plus the app in Docker

## Conventions verified from the code

- `AUTH_MODE` branches all auth behavior between `none`, `tailscale`, `oauth`, and `clerk` (see `.env.example` and `src/middleware.ts`)
- `src/generated/**` and `demos/**` are excluded from lint (`eslint.config.mjs`) and are build output / example content, not app code to edit by hand
- `vitest.config.ts` sets `fileParallelism: false`, keep new tests safe to run sequentially
- Skills under `skills/` are thin pointers: the actual workflow content lives as curata pages, seeded on first run
